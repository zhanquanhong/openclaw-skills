# 使用指南

## 飞书使用

### 基础用法

```
/validate https://feishu.cn/docx/xxx
```

### 严格模式（评审用）

```
/validate --strict https://feishu.cn/docx/xxx
```

### JSON 输出（程序调用）

```
/validate --json https://feishu.cn/docx/xxx
```

## 评分标准

| 分数 | 等级 | 说明 |
|------|------|------|
| 90-100 | 优秀 | 可直接生成 WBS |
| 80-89 | 良好 | 建议修复小问题 |
| 70-79 | 合格 | 可生成 WBS |
| 60-69 | 需改进 | 建议修复后再生成 |
| <60 | 不合格 | 必须修复 |

---

## 5 个必填项

1. **任务类型标记** - 🆕新增/🔄优化/♻️复用/🗑️删除/🔗对接
2. **依赖关系** - 无 / 依赖 X.X 接口
3. **接口定义** - URL/参数/返回/错误码
4. **实现说明** - 文件路径 + 方法名
5. **验收标准** - 可执行的检查项

---

## 常见问题

### Q: 合规率多少分算通过？
A: 70 分以上通过，可以生成 WBS。

### Q: 模糊词有哪些？
A: "优化一下"、"大概"、"左右"、"很快"等，详见模糊词库。

### Q: 如何实现说明才具体？
A: 必须包含文件路径（如 `src/main/java/.../XxxController.java`）和方法名。

### Q: 验收标准怎么写？
A: 用检查项列表，包含具体指标（如"响应时间 < 200ms"）。

## 最佳实践

1. 写方案时对照模板
2. 完成后立即验证
3. 修复所有必填项问题
4. 争取 80 分以上

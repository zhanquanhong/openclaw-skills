# wbs-skill v3.2 交付指南

### 一、阶段概述

此阶段是将技术方案文档自动分解为可执行的任务清单。wbs-skill v3.2 通过自然语言调用，实现"下载即用、拖文档出 Excel"的体验，大幅降低 WBS 生成门槛，让非技术人员也能一键生成任务分解。

- **责任人**: 研发 Leader / 项目经理 / 技术负责人
- **核心目标**: 输入技术方案 → 自动输出结构化 WBS Excel，支持自然语言调用，越用越聪明
- **AI 定位**: 意图解析 + 白名单学习，自动识别章节、接口表格、任务描述；用户可通过自然语言聚焦/排除特定类型任务
- **适用格式**: PDF、DOCX、Markdown（.md）

---

### 二、常规做法

**输入清单**:

| 输入项 | 格式 | 来源 | 用途 |
|--------|------|------|------|
| 技术方案文档 | PDF / DOCX / MD | 架构师 / 技术负责人 | 任务拆解的核心输入 |
| 用户白名单（可选） | YAML | 历史项目积累 | 提高识别率和命名标准化 |

**安装流程（只跑一次）**:

1. 从 GitHub 下载 `wbs-skill-v3.2.zip`，解压到任意目录
2. 执行安装脚本：`chmod +x install.sh && ./install.sh`（Mac/Linux）或双击 `install.bat`（Windows）
3. 验证安装：执行 `./wbs.sh`，看到帮助信息即成功

**执行流程**:

1. 将技术方案文档放到 `input/` 目录，或使用绝对路径指定
2. 执行 `./wbs.sh input/技术方案.pdf` 生成完整任务分解
3. 审查生成的 Excel，补充遗漏任务，确认即完成
4. 新任务自动学习到用户白名单，下次使用识别率提升

**wbs-skill 调用标准——支持 3 种调用方式**:

| 调用方式 | 示例 | 适用场景 |
|----------|------|----------|
| **默认模式** | `./wbs.sh input/方案.pdf` | 首次使用、需要完整结果 |
| **自然语言模式** | `./wbs.sh 方案.pdf "重点标出接口任务"` | 聚焦特定类型任务 |
| **指定模板模式** | `./wbs.sh 方案.pdf --section-template chinese` | 章节编号非数字格式 |

**输出物**: `output/WBS_技术方案_20260510_143022.xlsx`

**Excel 包含 7 列**:

| 列名 | 说明 |
|------|------|
| 任务模块 | 任务所属模块（自动推断或白名单匹配） |
| 任务 ID | 顺序编号 T001、T002... |
| 任务内容 | 标准化后的任务描述 |
| 任务来源 | 精确到章节 + 行号 |
| 任务类型 | 新增接口 / 更新接口 / 普通任务 |
| 依赖 | 同模块内自动推断依赖链 |
| 可验收标准 | 根据任务类型自动生成验收标准模板 |

**质量卡点与 DoD**:

- 任务来源精确到章节 + 行号，可追溯
- 每个任务有明确的验收标准
- 同模块内任务依赖链清晰，跨模块不自动依赖
- 接口任务自动标注"新增接口"或"更新接口"
- 输出目录自动保留最新 10 份，旧文件自动清理
- 白名单自动学习，git pull 不丢失用户数据

### 三、场景案例

---

**【场景 1 · 新项目首次使用】** ✅ 已验证

**选择条件**: 无历史白名单积累，首次使用 wbs-skill

**工具组合**: wbs-skill v3.2 + 人工审查

**执行过程**:

1. 准备技术方案文档（PDF/DOCX/MD）
2. 执行 `./wbs.sh input/技术方案.pdf` 生成初始 WBS
3. 人工审查生成的 Excel：
   - 补充遗漏任务
   - 修正任务描述
   - 调整依赖关系
4. 确认后，新任务自动学习到用户白名单
5. 下次同类项目自动生成时识别率提升

**关键约束**:

- 首次使用建议先用默认模式，不急于用自然语言过滤
- 审查后补充的任务会被自动学习，后续项目越来越准
- 技术方案质量直接影响生成质量（见"技术方案编写指南"）

**适用范围标签**: [通用] [新项目] [首次使用]

---

**【场景 2 · 类似方案复用】** ✅ 已验证

**选择条件**: 已有用户白名单积累，技术方案格式相似

**工具组合**: wbs-skill v3.2 + 用户白名单

**执行过程**:

1. 放入新的技术方案文档
2. 执行 `./wbs.sh input/新方案.pdf`
3. 白名单自动匹配，任务命名标准化
4. 新任务自动提示学习

**关键优势**:

- 任务命名与历史项目保持一致
- 减少人工修正成本
- 识别率随使用次数递增

**适用范围标签**: [通用] [存量迭代] [格式相似]

---

**【场景 3 · 聚焦特定类型任务】** ✅ 已验证

**选择条件**: 技术方案包含多类任务，只需关注某一部分

**工具组合**: wbs-skill v3.2 + 自然语言意图解析

**执行过程**:

1. 执行 `./wbs.sh 技术方案.pdf "重点标出接口任务"`
2. 自然语言意图解析 → 后置过滤 → 输出聚焦结果
3. 如需完整结果，不加引号参数重新生成

**自然语言调用示例**:

| 用户输入 | 过滤效果 |
|----------|----------|
| `"重点标出接口任务"` | 只保留含"接口"关键词的任务 |
| `"只分解后端开发部分"` | 聚焦后端/服务端相关任务 |
| `"排除运维相关任务"` | 过滤掉运维/部署/监控任务 |
| `"按周分解，重点标出接口任务"` | 周粒度 + 聚焦接口 |
| `"排除运维，只看后端接口"` | 排除运维 + 聚焦后端接口 |

**关键约束**:

- 关键词匹配准确率约 80%，可能出现漏杀/误杀
- 重要项目建议先生成完整结果，再人工筛选
- 自然语言参数不影响原始分解准确度，只做后置过滤

**适用范围标签**: [通用] [聚焦过滤] [自然语言调用]

---

**【场景 4 · 团队共享白名单】** ✅ 已验证

**选择条件**: 多个项目/团队成员需要统一任务命名标准

**工具组合**: wbs-skill v3.2 + 白名单导出/导入

**执行过程**:

1. 项目负责人导出白名单：`python3 generate_wbs.py --export team_whitelist.yaml`
2. 将 `team_whitelist.yaml` 分发给团队成员
3. 团队成员导入：`python3 generate_wbs.py --import team_whitelist.yaml`
4. 团队共享白名单后，识别率共同提升

**关键优势**:

- 团队任务命名一致
- 新人上手即用
- 白名单可随 Git 提交（官方白名单）或独立分发（用户白名单）

**适用范围标签**: [通用] [团队协作] [知识沉淀]

**【Prompt · 任务识别规则引擎】**

分级：[L1-核心]

wbs-skill 内置任务识别规则引擎（`src/rules.py`），通过正则表达式自动从技术方案中提取任务。

**任务识别规则（TASK_PATTERNS）—— 按优先级排列**:

| 优先级 | 规则类型 | 匹配模式示例 | 输出模板 |
|--------|----------|-------------|----------|
| 1 | REST API | `(GET|POST|PUT|DELETE) + (/api/[\w/-]+)` | `实现 REST API：{method} {path}` |
| 2 | 外放接口 | `外放接口`、`对外接口`、`开放接口` | `实现外放接口` |
| 3 | 接口开发 | `(.+接口)` | `实现{target}接口开发` |
| 4 | 功能开发 | `(.+功能)`、`实现.*功能` | `实现{target}功能开发` |
| 5 | 逻辑开发 | `(.+逻辑)`、`业务逻辑` | `实现{target}逻辑开发` |
| 6 | 配置调整 | `(.+配置)`、`Nacos 配置` | `调整{target}配置` |
| 7 | 查询/管理 | `(.+查询)`、`(.+管理)`、`(.+列表)` | `实现{target}查询/管理/列表功能` |

**模块识别规则（MODULE_PATTERNS）**:

| 关键词 | 识别模块 |
|--------|----------|
| 技能中心、技能管理、1.2.1 | 技能中心 |
| 对话管理、会话管理、1.2.2 | 对话管理 |
| 渠道模块、渠道管理、1.2.3 | 渠道模块 |
| mClaw、M-Claw、1.2.4 | mClaw 模块 |
| 定时任务、任务调度、1.2.5 | 定时任务模块 |
| 代理、大模型、LLM、1.2.6 | 代理模块 |
| 外放接口、开放平台、1.3 | 外放接口模块 |

**任务内容清洗规则**:
- 移除重复词：`功能功能开发` → `功能开发`
- 移除冗余前缀：`实现 XXX` → `XXX`
- 移除章节号：`1.2.1.2.1 XXX` → `XXX`
- 截断过长内容：>60 字取前 60 字

适用范围：[公司通用]

| **LOGIC** | 逻辑、计算、处理 | ①业务逻辑正确②边界条件处理完善③单元测试覆盖率>80%④代码审查通过⑤性能测试通过 |

| **DATA_RECORD** | 记录、存储、写入、表 | ①数据正确写入数据库②数据字段完整③数据格式正确④数据可正确查询⑤数据一致性保证 |
| **PAYMENT** | 扣费、扣减、token 数 | ①扣费金额计算正确②扣费前余额校验③扣费后余额更新正确④扣费记录完整⑤扣费失败有回滚机制 |
| **POLLING** | 轮询、等待、查询结果 | ①轮询间隔正确②轮询超时处理完善③轮询结果正确存储④轮询失败有重试机制⑤轮询状态可查询 |
| **CALCULATION** | 公式、计算 | ①计算公式正确②边界值计算正确③计算结果精度符合要求④计算性能达标⑤计算结果可追溯 |

**【Prompt · 自然语言意图解析规则】**

分级：[L1-核心]

wbs-skill 内置意图解析引擎（`src/intent_parser.py`），将用户自然语言转换为结构化参数。

**意图解析规则 —— 5 大维度**:

| 维度 | 关键词映射 | 解析结果 |
|------|-----------|----------|
| **章节模板** | 中文/一、/（一） | `chinese` |
| | markdown/md/# | `markdown` |
| | 混合/混排 | `mixed` |
| **分解粒度** | 按周/周分解 | `weekly` |
| | 按天/天分解 | `daily` |
| **聚焦关键词** | 重点/关注/只看 + 接口 | `["接口"]` |
| | 重点/关注/只看 + 后端 | `["后端"]` |
| **排除关键词** | 排除/去掉 + 运维 | `["运维"]` |
| | 排除/去掉 + 前端 | `["前端"]` |
| **任务类型** | 后端/服务端/Java | `["backend"]` |
| | 前端/Vue/React | `["frontend"]` |
| | 接口/API/REST | `["api"]` |
| | 数据库/表/SQL | `["database"]` |
| | 部署/Docker/K8s | `["devops"]` |

**冲突消解规则**:
- 当"排除"和"任务类型"同时匹配时，排除优先级更高
- 例如"排除运维"→ 只设置 exclude_keywords=["运维"]，不设置 task_types=["devops"]

**兜底策略**: 匹配失败时返回默认参数（numeric 模板 + 默认粒度 + 无过滤），不影响核心流程

适用范围：[公司通用]

分级：[L1-通用]

| 字段 | 内容 |

| **适用范围** | 所有使用 wbs-skill 的场景 |

| **验证方式** | `python3 generate_wbs.py --stats` 查看学习成果统计 |

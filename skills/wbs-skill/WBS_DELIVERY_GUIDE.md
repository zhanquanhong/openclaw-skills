# wbs-skill v3.2 交付指南

### 一、阶段概述

此阶段是将技术方案文档自动分解为可执行的任务清单。wbs-skill v3.2 通过自然语言调用，实现"下载即用、拖文档出 Excel"的体验，大幅降低 WBS 生成门槛，让非技术人员也能一键生成任务分解。

- **责任人**: 研发 Leader / 项目经理 / 技术负责人
- **核心目标**: 输入技术方案 → 自动输出结构化 WBS Excel，支持自然语言调用，越用越聪明
- **AI 定位**: 意图解析 + 白名单学习，自动识别章节、接口表格、任务描述；用户可通过自然语言聚焦/排除特定类型任务
- **适用格式**: PDF、DOCX、Markdown（.md）

#### 2.2 白名单从哪里来？

白名单**不是凭空产生的**，它的来源如下：

```
官方白名单（data/whitelist.yaml）
├── 来源：wbs-skill 工具包内置
├── 内容：32 个通用后端开发任务模板
├── 维护人：wbs-skill 项目维护者
├── Git 管理：✅ 纳入版本控制，随工具包同步更新
└── 作用：新工具首次使用时即可匹配基础任务

用户白名单（data/user_whitelist.yaml）
├── 来源：用户每次生成 WBS 后，新任务自动学习保存
├── 内容：用户项目特有的任务命名（首次使用为空）
├── 维护人：使用 wbs-skill 的用户
├── Git 管理：❌ 被 .gitignore 保护，防止 git pull 覆盖
├── 迁移：复制文件即可换电脑使用
├── 共享：导出后分发给团队成员，统一任务命名
└── 作用：第二次及以后使用时，任务识别率提升

白名单合并逻辑：
├── 官方白名单 + 用户白名单 → 合并加载
├── 同名任务：用户白名单优先
├── 匹配到的任务：使用白名单标准命名
└── 未匹配到的任务：作为"新任务"提示用户学习
```

### 三、常规做法

#### 3.1 安装流程（只跑一次）

**前置条件**：
- Python 3.8+ 已安装
- 从 GitHub 下载 wbs-skill-v3.2.zip

**步骤**:

1. 解压到任意目录
2. 执行安装脚本：`chmod +x install.sh && ./install.sh`（Mac/Linux）或双击 `install.bat`（Windows）
3. 安装脚本自动完成：
   - 检查 Python 环境
   - 创建虚拟环境 .venv
   - 安装依赖（PyPDF2、pdfplumber、openpyxl 等）
   - 创建 input/ output/ 目录
4. 验证安装：执行 `./wbs.sh`，看到帮助信息即成功

#### 3.2 执行流程

**前置条件**：
- 已安装 wbs-skill（安装流程）
- 已准备好技术方案文档（来自上游阶段二）

**步骤**:

1. **准备输入**：将技术方案文档放到 `input/` 目录，或使用绝对路径指定
2. **执行生成**：运行 `./wbs.sh input/技术方案.pdf`
3. **工具自动处理**：
   - 解析文档（提取章节、表格、文本）
   - 加载官方白名单 + 用户白名单（如有）
   - 提取任务 + 白名单匹配 + 标准化
   - 推断依赖 + 生成验收标准
   - 输出 Excel 到 output/ 目录
   - 新任务提示学习 → 保存到用户白名单
4. **人工审查**：检查生成的 Excel，补充遗漏任务
5. **确认完成**：新任务自动学习，下次使用识别率提升

**输出交付**：
- WBS Excel → 交给项目经理分配任务
- WBS Excel → 交给研发团队按任务 ID 开发
- 用户白名单 → 自动更新，供下次使用

#### 3.3 调用方式

| 调用方式 | 示例 | 适用场景 |
|----------|------|----------|
| **默认模式** | `./wbs.sh input/方案.pdf` | 首次使用、需要完整结果 |
| **自然语言模式** | `./wbs.sh 方案.pdf "重点标出接口任务"` | 聚焦特定类型任务 |
| **指定模板模式** | `./wbs.sh 方案.pdf --section-template chinese` | 章节编号非数字格式 |

#### 3.4 输出物

**文件**: `output/WBS_技术方案_20260510_143022.xlsx`

**Excel 包含 7 列**:

| 列名 | 说明 | 数据来源 |
|------|------|----------|
| 任务模块 | 任务所属模块 | 文档章节推断 + 白名单匹配 |
| 任务 ID | 顺序编号 T001、T002... | 工具自动生成 |
| 任务内容 | 标准化后的任务描述 | 白名单标准命名 或 文档原文提取 |
| 任务来源 | 精确到章节 + 行号 | 文档解析时记录位置 |
| 任务类型 | 新增接口 / 更新接口 / 普通任务 | 关键词匹配判断 |
| 依赖 | 同模块内自动推断依赖链 | 按模块分组 + 顺序推断 |
| 可验收标准 | 根据任务类型自动生成 | 内置验收标准模板匹配 |

#### 3.5 质量卡点与 DoD

- 任务来源精确到章节 + 行号，可追溯
- 每个任务有明确的验收标准
- 同模块内任务依赖链清晰，跨模块不自动依赖
- 接口任务自动标注"新增接口"或"更新接口"
- 输出目录自动保留最新 10 份，旧文件自动清理
- 白名单自动学习，git pull 不丢失用户数据

**【场景 1 · 新项目首次使用】** ✅ 已验证

**选择条件**: 无历史白名单积累，首次使用 wbs-skill

**输入**:
- 技术方案文档（PDF/DOCX/MD）← 架构师产出
- 官方白名单（工具包内置，32 个通用任务）
- 用户白名单：无（首次使用，data/user_whitelist.yaml 不存在）

**执行过程**:

1. 准备技术方案文档（PDF/DOCX/MD）
2. 执行 `./wbs.sh input/技术方案.pdf` 生成初始 WBS
3. 工具处理：
   - 解析文档 → 提取原始任务
   - 加载官方白名单（32 个） → 匹配标准化
   - 未匹配的任务 → 标记为"新任务"
   - 生成 WBS Excel
4. 人工审查生成的 Excel：
   - 补充遗漏任务
   - 修正任务描述
   - 调整依赖关系
5. 工具提示学习新任务 → 用户输入 Y 确认 → 保存到 user_whitelist.yaml
6. **产出**：
   - WBS Excel → 交付下游阶段
   - 用户白名单 → 新生成（从零到一），供下次使用

**数据流向**:
```
技术方案文档 + 官方白名单
       ↓
   wbs-skill 首次运行
       ↓
   WBS Excel（交付下游）+ 用户白名单（首次积累）
```

**关键约束**:

- 首次使用建议先用默认模式，不急于用自然语言过滤
- 审查后补充的任务会被自动学习，后续项目越来越准
- 技术方案质量直接影响生成质量（见"技术方案编写指南"）

**适用范围标签**: [通用] [新项目] [首次使用]

**【Prompt · 任务识别规则引擎】**

分级：[L1-核心]

wbs-skill 内置任务识别规则引擎（`src/rules.py`），通过正则表达式自动从技术方案中提取任务。

**输入**: 技术方案文档解析后的文本行列表
**输出**: 原始任务列表（含任务模块、任务类型、任务内容、原始描述）

**任务识别规则（TASK_PATTERNS）—— 按优先级排列**:

| 优先级 | 规则类型 | 匹配模式示例 | 输出模板 |
|--------|----------|-------------|----------|
| 1 | REST API | `(GET|POST|PUT|DELETE) + (/api/[\w/-]+)` | `实现 REST API：{method} {path}` |
| 2 | 外放接口 | `外放接口`、`对外接口`、`开放接口` | `实现外放接口` |
| 3 | 接口开发 | `(.+接口)` | `实现{target}接口开发` |
| 4 | 功能开发 | `(.+功能)`、`实现.*功能` | `实现{target}功能开发` |
| 5 | 逻辑开发 | `(.+逻辑)`、`业务逻辑` | `实现{target}逻辑开发` |
| 6 | 配置调整 | `(.+配置)`、`Nacos 配置` | `调整{target}配置` |
| 7 | 查询/管理 | `(.+查询)`、`(.+管理)`、`(.+列表)` | `实现{target}查询/管理/列表功能` |

**模块识别规则（MODULE_PATTERNS）**:

| 关键词 | 识别模块 |
|--------|----------|
| 技能中心、技能管理、1.2.1 | 技能中心 |
| 对话管理、会话管理、1.2.2 | 对话管理 |
| 渠道模块、渠道管理、1.2.3 | 渠道模块 |
| mClaw、M-Claw、1.2.4 | mClaw 模块 |
| 定时任务、任务调度、1.2.5 | 定时任务模块 |
| 代理、大模型、LLM、1.2.6 | 代理模块 |
| 外放接口、开放平台、1.3 | 外放接口模块 |

**任务内容清洗规则**:
- 移除重复词：`功能功能开发` → `功能开发`
- 移除冗余前缀：`实现 XXX` → `XXX`
- 移除章节号：`1.2.1.2.1 XXX` → `XXX`
- 截断过长内容：>60 字取前 60 字

适用范围：[公司通用]

**【Prompt · 验收标准自动生成模板】**

分级：[L1-核心]

wbs-skill 内置 8 类验收标准模板（`src/templates.py`），根据任务类型自动匹配生成。

**输入**: 任务类型（REST_API/FEATURE/LOGIC/CONFIG/DATA_RECORD/PAYMENT/POLLING/CALCULATION）+ 任务内容
**输出**: 5 条验收标准（分号分隔的字符串）

**【Prompt · 自然语言意图解析规则】**

分级：[L1-核心]

wbs-skill 内置意图解析引擎（`src/intent_parser.py`），将用户自然语言转换为结构化参数。

**输入**: 用户输入的自然语言字符串（如"按周分解，重点标出接口任务"）
**输出**: 结构化参数字典（section_template、granularity、focus_modules、exclude_keywords、task_types）

**意图解析规则 —— 5 大维度**:

| 维度 | 关键词映射 | 解析结果 |
|------|-----------|----------|
| **章节模板** | 中文/一、/（一） | `chinese` |
| | markdown/md/# | `markdown` |
| | 混合/混排 | `mixed` |
| **分解粒度** | 按周/周分解 | `weekly` |
| | 按天/天分解 | `daily` |
| **聚焦关键词** | 重点/关注/只看 + 接口 | `["接口"]` |
| | 重点/关注/只看 + 后端 | `["后端"]` |
| **排除关键词** | 排除/去掉 + 运维 | `["运维"]` |
| | 排除/去掉 + 前端 | `["前端"]` |
| **任务类型** | 后端/服务端/Java | `["backend"]` |
| | 前端/Vue/React | `["frontend"]` |
| | 接口/API/REST | `["api"]` |
| | 数据库/表/SQL | `["database"]` |
| | 部署/Docker/K8s | `["devops"]` |

**冲突消解规则**:
- 当"排除"和"任务类型"同时匹配时，排除优先级更高
- 例如"排除运维"→ 只设置 exclude_keywords=["运维"]，不设置 task_types=["devops"]

**兜底策略**: 匹配失败时返回默认参数（numeric 模板 + 默认粒度 + 无过滤），不影响核心流程
